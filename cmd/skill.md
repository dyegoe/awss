# awss: search AWS across profiles and regions

awss {{.Version}} wrote this skill (`awss skill`). awss runs one search per profile and region, in
parallel, and prints the results of each. It reads only, except `awss cleanup`.

## Before you run a command

1. Pick the command from the list or the question map below.
2. Read `awss <command> --help` before you use a flag you have not seen in this session. The help
   is generated by the installed binary, so it is always right: it lists the flags, their
   accepted values, the sort fields and, at the end, the **Fields** of the result.
3. Choose the config file, the profiles and the regions (see below).
4. Always add `--output json` and read the result with `jq`. Never parse the table: its cells hold
   several lines and some fields are in the JSON only (the Fields section says which).

## Commands

{{.Commands}}

`awss cloudwan`, `awss dx` and `awss tgw` only group their subcommands: run `awss tgw routes`,
not `awss tgw`.

## Reading the JSON

`--output json` prints one JSON object per line, one per profile and region searched:

```json
{"profile":"network-prd","region":"eu-west-1","errors":[],"data":[{"id":"vpc-0123","name":"core"}]}
```

- The rows are in `.data[]`; their field names are in the Fields section of `--help`.
  Example: `awss rds --all --output json | jq -r '.data[] | [.id, .endpoint] | @tsv'`.
- Each profile and region carries its own `.errors`. Check them on every run: no rows in a
  result set with an error does **not** mean nothing is there. List them with
  `jq -r 'select(.errors | length > 0) | "\(.profile) \(.region): \(.errors[])"'`.
- Empty result sets are left out unless `--show-empty` is set.
- Global services run once per profile and show the region `global`: `awss org`,
  `awss cloudfront`, `awss cloudwan` and `awss dx`. Do not add `--regions` to them.
- When a search fails, awss prints one summary line on stderr and still exits 0. `--stats`
  prints run statistics on stderr too, so stdout stays valid JSON.
- `--timeout` (default 5m) bounds the whole run. A profile and region still running at the
  deadline is reported with a "timed out" error and no rows; raise `--timeout` for a large run
  instead of reading it as empty.

## Choosing --config, --profiles and --regions

- Use exactly the config, profile or region the user names.
- Otherwise look before you guess. The config files are `~/.awss/*.yaml`; `--config devops-lz2`
  reads `~/.awss/devops-lz2.yaml`, and `AWSS_CONFIG` sets it for the shell. Read the chosen file:
  `all-profiles` is what `--profiles all` expands to, and `all-regions` what `--regions all`
  expands to. With no `all-profiles`, the profiles are the sections of `~/.aws/config`.
- When two config files could fit (such as a legacy and a new landing zone), ask the user which.
- Start narrow: the profiles and regions the question is about. Use `--profiles all` or
  `--regions all` only when the question really is "anywhere", and tell the user before you run
  it: it can be thousands of searches.
- Never log in for the user. A profile whose session expired reports an error in its result set:
  name the profile and suggest they log in (for example `granted` or `aws sso login`), then run
  again.
- `--org-profile <profile>` adds the account names of the AWS Organization to the Owner columns
  (it needs `organizations:ListAccounts`). Use it only when the user gives that profile or the
  config file sets `org-profile`.

## Question map

For questions whose command is not obvious from its name. Read each command's `--help` first.

- **Which route does an IP or CIDR take?** In a Transit Gateway:
  `awss tgw routes --cidrs <ip> --match longest`. In Cloud WAN:
  `awss cloudwan routes --cidrs <ip> --match longest`. The row names the attachment the route points
  to; `awss tgw attachments` and `awss cloudwan attachments` say what that attachment is.
- **Why is a route missing in Cloud WAN?** `awss cloudwan bgp --cidrs <cidr>` shows the BGP
  routes before the routing policies, and whether each one was installed.
- **Who owns an IP address?** `awss eni --private-ips <ip>` (or `--public-ips`): the network
  interface, its subnet, instance and owner account.
- **Which instances are inside a CIDR?** `awss ec2 --cidrs <cidr>`: any private IP of any network
  interface inside the range.
- **Which VPC or subnet has this exact CIDR?** `awss vpc --cidrs <cidr>` and
  `awss subnet --cidrs <cidr>` match the CIDR block exactly.
- **Which instance uses this volume?** `awss ebs --ids <volume-id>`.
- **Which database runs this engine or version?** `awss rds --engine-versions <glob>` for DB
  instances, `awss rds-cluster --engine-versions <glob>` for Aurora and Multi-AZ DB clusters.
- **Which account is this ID, or what accounts exist?** `awss org` with the profile that can read
  the organization.
- **What does a data centre receive over Direct Connect?** `awss dx gateways --cidrs <cidr>`:
  the allowed prefixes of the gateway associations.
- **Where is this object?** `awss s3obj --buckets <glob> --keys <glob>`.

## Cleanup commands change AWS

`awss cleanup default-vpc` and `awss cleanup dhcp-options` delete resources. Without `--apply`
they only report a plan: run them that way and show the plan. Never add `--apply` (or
`--confirm-all`) unless the user asks for the deletion after seeing the plan.
